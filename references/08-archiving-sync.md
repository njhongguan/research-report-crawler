# 08 · 归档与同步（流式中转 · 即推即删）

> 场景：本地/云端磁盘装不下全量语料，要归档到网盘（Google Drive 等）。
> 约束：**云端磁盘可能只剩几个 GB**，而语料有十几 GB。

---

## 一、核心思路：分批中转 + 即推即删

```
本地 reports/ ──tar 流──▶ 云端 staging/ ──rclone copy──▶ 网盘
                              │                            │
                              └──── 入库成功 ──▶ rm -rf ───┘
                                   （释放云端空间）
```

**关键点**：云端磁盘只当**中转站**，同一时刻只驻留「一批」的数据。
入库成功后立刻删本地中转 → 云端水位恒定。

---

## 二、四条硬约束

| # | 约束 | 值 / 判据 |
|---|---|---|
| 1 | **单批大小** | 500~800MB（太小效率低，太大撞磁盘红线） |
| 2 | **磁盘熔断** | 云端可用空间 **< 2048MB 立即停**（每批前 `df -m /` 检查） |
| 3 | **入库成功才删** | 删之前必须核验（见下） |
| 4 | **断点续传** | 台账 `gdrive_sync_ledger.json` + 云端清单**双判重** |

---

## 三、★★★ 五个决定成败的参数

### 1. 入库并发决定一切

| `--transfers` | 速度 |
|---|---|
| 4 | **4.77 s/文件** |
| **16** | **0.4 s/文件** ← 12× 提速 |

### 2. 但并发撞内存红线 → OOM

**内存安全线**：`transfers × (buffer + chunk) ≤ 450M`

| 配置 | 内存 | 结果 |
|---|---|---|
| `16 × (8M + 4M)` | 192M | ✅ 安全 |
| `16 × 32M` | 512M | ❌ **OOM**（rc=137，连旁路服务一起被杀） |

★ 用 `systemd-run --scope -p MemoryMax=450M` 给归档进程套上内存上限，
OOM 时只杀它自己，不牵连其他服务。

### 3. `--fast-list` 反而拖慢

**实测**：333 个文件用 `--fast-list` 花了 **841s** → **去掉**。

### 4. `--drive-chunk-size` 别贪大

`4M` 够用；`32M` 会 OOM（见上）。

### 5. ★★★ 上传后必须核 `mtime`

**坑**：修复了脚本，**以为**传上去了，但云端文件 `mtime` 没变 = **没生效** →
下一轮又产出一批重复文件。

→ **核验不只是「文件存在」，而是「文件是新传的」**。

---

## 四、核验（verify）的两个陷阱

### 1. 核验命令会被 sshd 截断

目录多时（如某大类 350 个子目录 ≈ 2.8 万字符），一条 ssh 命令太长 →
`sshd` 截断 → `syntax error: unexpected end of file`。

→ ★ **分块**：**每 60 个目录一次 ssh**。

### 2. 证「0 缺口」后要清失败台账

`--verify` 证明「本地有云端缺 = 0」之后，
**必须清掉失败记录文件**，否则下一轮会**误报残留**。

---

## 五、验收标准（示例）

| 指标 | 目标 | 实测 |
|---|---|---|
| 网盘篇数 | ≥ 7,400 | **17,218** |
| 网盘容量 | ≥ 9.0 GB | **15.32 GiB** |
| 云端磁盘剩余 | ≥ 2.5 GB | **6,251 MB** |
| 路径一致性 | 100% | ✅ |
| 本地有云端缺 | 0 | ✅ **0** |
| 熔断次数 | — | **0** |

---

## 六、路径一致性（结构规范）

网盘上的结构必须与本地**完全一致**：

```
<根>/<大类>/<站名>/<YYMMDD>_<标题>.pdf
```

**踩过的坑**：归档工具自动加了**日期前缀文件夹**（如 `20260930_reports/`）→
结构变成 `<根>/<日期>_reports/<大类>/...` → 与本地不一致 → 下游对账失败。

→ **去掉日期前缀文件夹**，让结构严格等于本地相对路径。

★ 改完工具后要**核 `mtime`** 确认真的生效（见上）。

---

## 七、同步（本地 ↔ 云端）的合并规则

| 文件类型 | 合并方式 |
|---|---|
| **索引类 JSON**（简报 / 摘要 / link_map） | ★ **按 key 合并**（不是覆盖） |
| **`seen_links.json`** | ★ **双向并集** |
| **产物文件**（pdf/html） | 按路径去重（同名同大小跳过） |
| **配置** | ★ **两边分别改**，严禁整文件覆盖 |

★★★ **不可恢复的数据**：AI 简报只存在 JSON 里（PDF 不注入摘要）
→ 覆盖即永久丢失（曾一次冲掉 ~800 条）。
→ 所以：**带锁写入 + 只补空不覆盖 + 写前备份**。

---

## 八、断点续传台账

```jsonc
// gdrive_sync_ledger.json
{
  "batches": [
    {"id": "b0001", "dirs": ["reports/宏观经济/Fed"], "files": 42,
     "bytes": 512000000, "status": "done", "ts": "2026-10-12T03:11:00"}
  ],
  "failed": [{"path": "reports/.../x.pdf", "reason": "timeout"}]
}
```

- 每批开始前：查台账 + 查云端清单 → **双判重**，已完成的跳过。
- 每批成功后：写台账（**原子写**）。
- 失败项单独记 `failed`，供 `--retry-failures` 重跑。

---

## 九、清理原则（复习）

★ **隔离/清理一律 `shutil.move` 到 `_quarantine_*/`，绝不 `rm`。**
★ 清理计划脚本默认 **dry-run**，`--apply` 才真动，且产出 **manifest**（移动清单）。

# 03 · 反爬处置手册（最常翻的一篇）

> **先判「拦截类型」，再选「场景」。本地与云端能力互补，不是二选一。**

## 一、决策表：拦截类型 → 用哪个场景

| 拦截类型 | 识别特征（照抄进判据） | 首选场景 | 落地开关 / 破法 |
|---|---|---|---|
| **Cloudflare JS 挑战** | `Just a moment...` / `请稍候…` / 5.6~5.9KB | **本地** | `via_node:auto`；靠 12~45 次节点轮换，单次通过率 40~46% |
| **CF TLS 层概率拒绝** | `SSL alert 40`（只读 7B 就掐） | **本地** | `use_cffi:true` + chrome131 指纹 |
| **Akamai 边缘拒绝** | `Access Denied` + `errors.edgesuite.net`，**377~473B** | **云端** | 换通道即可（海外 IP 直连就过） |
| **S&P 自研 WAF** | `Security Controls Triggered`，**~2KB** | **本地** | `via_node:true` + `node_retries:45`（浏览器节点通道） |
| **Vercel** | `Vercel Security Checkpoint` + 429 | **云端** | 节点通道（真 Chrome）实测可过 |
| **CEDEFOP 自研网关** | `Verification Required` + `/validate` | **本地** | 节点；★ 有状态风控，`?page=N` 会**加重**挑战 |
| **Azure WAF** | `<title>Azure WAF</title>`，href 去重 = 1 | **未攻克** | 暂无 |
| **地域限制** | 直连超时 / 拒绝 | **云端** | 海外 IP（如加拿大统计局） |
| **软 404** | **HTTP 200** + 合法 HTML，`<title>` 说「找不到」 | 改 pattern | `is_error_page()`（只看 title/h1） |
| **登录墙 / 付费墙** | `<title>`/`<h1>` = `Log in to view this page` | 换源 | ★ `is_error_page()` **不覆盖** → 走产物审计脚本 |
| **SPA 空壳** | HTTP 200、`hrefs < 12`、无文章链接 | 换入口 | 官方 API / sitemap / `use_js` |

## 二、三步定位法（拿到一个抓不到的站）

```
① 本地直连（curl_cffi）—— 看【响应体大小】，不是看状态码
     ├─ 大页 100KB~1MB      → 概率性拦截 → 【本地】节点通道多试（8 次 ≈99%）
     ├─ 恒 ~6KB / 473B 小页 → 硬封        → 【云端】换出口
     └─ 200 但 hrefs < 12   → SPA 空壳    → 换入口（API / sitemap / use_js）

② 云端直连 —— 同上判据

③ 两个场景都拿不到 → 换【入口】而不是换【通道】
     官方 API → 官方 RSS/Atom → 静态 JSON → sitemap.xml → 最后才爬 HTML 列表页
```

> **★ 反直觉但最高频的一条：「有内容 + 0 命中」= 改 pattern；「无内容」= 改通道。**
> 实证：某站节点拿到 1MB 真页却命中 0 → 是 pattern 路径写错（旧 `/research-insights/...`
> vs 真实 `/research/article/`），**不是封锁**。

## 三、★★★ 概率性拦截 vs 硬封禁（最高价值判据）

**判据：同一 URL 反复请求，结果随机 = 概率性 → 重试可解；每次都在同一位置失败 = 真封禁。**

| 现象 | 结论 | 处理 |
|---|---|---|
| 同 URL 连打 5~12 次，通过率在 0~100% 之间跳 | **概率性** | 加大重试（`node_retries`） |
| 响应体是大页（100KB~1MB） | 概率性 | `use_cffi` 有效 |
| 每次都是恒 **~6KB 403 小页** | 硬封 | 换场景 |
| 每次都是恒 **473B / 2011B** | 硬封（该 IP/通道） | 换通道或换 IP |

**必须做阳性对照**：测通过率时**同时刻**打一个「已知能通的站」。
否则分不清「站点封了」和「探测工具自己坏了」（探测跑久了会 **0.0s 瞬败**）。

> 实证：某站曾被判「永久封禁」→ 同一分钟连打 12 次，**成功 10 次（83%）**。

### ★★★ 但「加大重试」有反噬 —— 最贵的一课

某站一开始把 `node_retries` 提到 **45**（3 轮 × 15 节点，理论 ≈96%）。
**结果：连续猛打之后，Akamai 按「速率」把整个节点 IP 段封了** ——
封禁前同一批节点首试就拿到 1MB 真页；封禁后 3 个节点全部返回 **330~480B `Access Denied`**，
而且**后续所有运行都失败**（连带把原本能过的节点也拖黑）。

> **结论：对 Akamai 这类「按速率封禁」的站点，重试次数不是越多越好 —— 越多死得越快。**
> 正确姿势是 **「中等重试（≤20）× 分多次跑」**，靠 `seen` 合并把内容逐步累积起来。

| 拦截类型 | 重试策略 |
|---|---|
| **Cloudflare**（按 IP 概率放行，不按速率封） | 可加大到 8~12 次；多节点轮换有效 |
| **Akamai**（按速率封 IP 段） | **≤20 次，且不要连续跑**；失败就隔几小时再来 |
| **自研 WAF** | 同上，保守 |

**判断自己是否已触发速率封禁**：看失败响应体的**形态变化** ——
原本能过 → 现在**所有节点都返回同一个固定小体积拒绝页**（473B / 330B）→ 就是被按速率封了，
此时**继续重试只会延长封禁**。

## 四、两个抓取场景

| | **场景 A · 中国本地** | **场景 B · 海外云端** |
|---|---|---|
| 出口 IP | 中国大陆住宅 | 韩国机房（阿里云） |
| 主力武器 | **节点通道**（xray 多节点轮换 + 真实 Chrome） | **直连**（海外 IP）+ 节点池 |
| 强项 | **过 Cloudflare**（出口 IP 是唯一有效变量） | **过 Akamai / 地域限制** |
| 弱项 | 过不了部分地域限制站 | 节点池较弱、内存小 |
| 命令 | `python crawler.py crawl --only <关键词>` | `FORCE_HEADLESS=1 venv/bin/python crawler.py crawl` |

**实证（同一天、同一份配置）**

| 站 | 本地 | 云端 | 谁赢 |
|---|---|---|---|
| BCG-波士顿咨询 | 0 产出 | **PDF 6** | 云端 |
| StatCan-加拿大统计局 | 0 产出 | **HTML 6** | 云端 |
| CEDEFOP | 概率性拦截 | **PDF 1** | 云端 |
| IMF-工作论文 | **PDF 17** | 0 链接 | 本地 |
| OECD-经合组织 | 有产物 | 0 链接 | 本地 |
| SPGlobal-指数研究 | **首试即通**（1MB） | 1/15 通过 | 本地更稳 |

> **结论**：本地 + 云端**都跑**，才能覆盖全部站点。
> 单靠任何一边，都会有一批站「静默 0 产出」而**不报错**。

## 五、★★★ 零产物站三分诊（处置完全相反）

| 类别 | 判据 | 处置 |
|---|---|---|
| **① 节点池对该站无效** | 专门针对该站扫节点仍 **0 通过** | ★ **不建议盲投时间**（产出低、成本高） |
| **② 入口 URL/结构已变** | 过 CF 但**全路径整齐 404** | ★★ **改配置就能救，优先做** |
| **③ 站点侧 5xx / 连接失败** | 直连 `000` 或 `500` | 等站点恢复；不是反爬 |

★★★ **节点白名单是「按站扫的」，不能跨站复用**。
针对 `iea.org` 扫出的 65 个节点，换到另一个站 **0/36 通过**（专门重扫也一样）。
→ 所以「零产物站」的根因**分三类**，别混为一谈。

### 类别 ② 的修复范式（「入口失效」可复用）

- **病根**：`list_url` 写的是已废弃的栏目（节点下全 404）。
- **定位手法**：节点通道抓**站点根** → 抽 `href="(/[^"#?]*)"` → 拿到栏目路径 →
  实测哪个栏目是 200 真内容。
- **新配置**：换 `list_url` 到真栏目；`link_pattern` 只匹配内容目录下的长 slug
  （排除 `feed` / `wp-json` / `category` / 人名）。
- ★ 分页可能被 CF 缓存成与第一页**相同**（只拿到部分）。

## 六、节点通道的环境依赖（★ 缺一即**静默失效、不报错**）

| 依赖 | 缺失症状 |
|---|---|
| `alive_nodes.json`（白名单） | 取节点列表的函数**直接 `return []`** —— 无任何报错 |
| xray 二进制 | `⚠️ 节点通道不可用（xray 不存在）` |
| **playwright + Chrome** | 浏览器启动处抛异常 |

### ★★★ 孤儿节点通道（最坑的环境问题）

杀掉主进程后，xray 可能残留 → 端口被占 → **所有依赖站静默失败**。

- 识别：**必须靠命令行特征**，不能靠进程名。本项目 xray 含 `_xraytest`，Chrome 含 `headless`/`scoped_dir`。
- 本机常态：**v2rayN 的 xray 恒有 1 个**（命令行不含 `_xraytest`）→ **不能杀**。
- 判据：`netstat -ano | grep -cE "127.0.0.1:2060[0-5].*LISTENING"` 应为 **0**。

### ★★★ 白名单会过期

实测 23.7h 未更新 → 大量节点站取不到内容。
刷新命令 `python cf_fetch.py scan` —— **但它会直接覆盖白名单** → 必须先备份、扫完用合并脚本并回。

## 七、四个「探测数字骗自己」的口径陷阱

| # | 陷阱 | 真相 |
|---|---|---|
| ① | 403 挑战页被归成「无响应」 | 有响应，只是被拦 —— 判据要看**响应体** |
| ② | 200 真页 ≠ 能抓 | SPA 空壳（`hrefs < 12`）也是 200 |
| ③ | 主站被拦 ≠ 机构拿不到 | `www.imf.org` 403 ❌ / `elibrary.imf.org` ✅（**换子域**） |
| ④ | 探测工具会自己坏 | 跑久了会 0.0s 瞬败 → 每 4 源跑一次**阳性对照** |

**另两条诊断纪律**
- 验收看**产物**不看日志；「指标变好」要分清是修好了还是把东西藏起来了。
- **`grep -v "WARNING"` 会吃掉日志的 `[WARNING]` 行**（SSH post-quantum 警告过滤习惯导致）
  → 正确写法：`grep -v "post-quantum\|store now\|openssh.com\|vulnerable"`。

## 八、「抓不到」的四种解法（按成本递增）

1. **换子域**（`www.` → `news.` / `elibrary.`）—— 零成本，先试
2. **换通道**（直连 ↔ 代理 ↔ 节点 ↔ 云端海外 IP）
3. **换入口**（HTML 列表 → 官方 API → RSS → sitemap → 静态 JSON）
4. **换 IP**（换节点池 / 换机房区域）

★ **「走代理被拦、直连反而通」真实存在** → `no_proxy:true`
（实证：代理拿 5.5KB 挑战页，直连拿 308KB 真页）。
**代理不是默认更好的通道，是要验证的变量。**

# 04 · 产物真伪闸门（4 类静默污染）

> **语料库最危险的失败不是「没数据」，而是「坏数据混进来」。**
> 「没抓到」是**可见**的（目录空着）；「抓错了」是**不可见**的 ——
> 一个截断 PDF、一张 `400 Bad Request` 页面，会被计入产物、进索引、送 AI，然后以「数据」的身份流通下去。

判断语料库健康与否，看的不是文件数，而是**这四类静默污染有没有被堵住**：

| # | 静默污染 | 表象 | 真判据 |
|---|---|---|---|
| ① | **截断件** | 文件存在、有 `%PDF-` 头、大小正常 | 尾部**有没有 `%%EOF`** |
| ② | **错误页入库** | 有标题、有内容、能送 AI | 标题**是不是 HTTP 状态行**（含「软 404」形态） |
| ③ | **重复重抓** | 日志正常、看起来在干活 | `seen` **有没有真的写进去** |
| ④ | **通用 PDF 污染** | 产物是 PDF、有 `%%EOF`、判据全过 | **多篇产物的 MD5 是否互异** |

---

## ① 截断件

**成因**：代理反而比直连慢 → 大文件撞下载超时上限 → 只落了 `%PDF-` 头。
（实测：本地直连 0.1 MB/s + 代理 TLS 断；同一文件云端直连 **7 MB/s**。）

**判据**（`is_complete_pdf()`）：
1. 读文件头确认是 `%PDF-`；
2. 若有 `Content-Length` 或 `/L`（PDF 内部长度字段）→ **只信 `size < L`** 这一种判定；
3. **尾部 2048 字节必须能搜到 `%%EOF`**。

**处置**：截断件**隔离**（`shutil.move` 到 `_quarantine_truncated_*/`），并从 `seen` 放出 URL 让它重抓。

---

## ② 错误页入库

**成因**：HTTP 200 + 合法 HTML，但内容是错误页。
★★★ **错误页的 `<title>` 是「非空」的**（`400 Bad Request`），所以「标题非空」不能当有效性判据。

**三种形态**：

| 形态 | 特征 | 判据 |
|---|---|---|
| 标准错误页 | `<title>400 Bad Request</title>` | 标题匹配 HTTP 状态行正则 |
| **软 404** | `<title>404error：站点名</title>` | ★ 无空格 + 小写 + 全角冒号 → **标准正则漏判** |
| 登录墙 | `<title>Log in to view this page</title>` | 正文 ~1,000 字 → **主判据不覆盖** |

**判据**：`is_error_page(html)` 看 `<title>` 与 `<h1>`；
软 404 需要**头部特征匹配**（`_SOFT_404_TITLE_RE` / `_SOFT_404_HEAD_RE`）。

**处置**：`audit_artifacts.py` 批量扫描 → 隔离 → **同时从 `seen` 放出**（否则永远重抓不到）。

---

## ③ 重复重抓（`seen` 没写进去）

**成因**：抓一半被中断 → `seen` 没写入 → 下轮整站重抓。或反过来：`seen` 写了但产物没落盘。

**两个方向都要查**：

| 症状 | 判据 | 工具 |
|---|---|---|
| 有产物、无 `seen` | 下轮会重复抓 | 正常（幂等），但要确认不会重复下载 |
| `seen` 有、**无产物** | ★ 该 URL 被永久跳过 | `_purge_seen.py "<子串>" --apply` 放出 |

**设计原则**：`seen` **只在成功后写**。抓一半崩溃 → 不记账 → 下轮重抓（幂等优先）。

---

## ④ 通用 PDF 污染（最隐蔽）

**成因**：「PDF 优先」策略会命中详情页**页脚的全站通用 PDF**（隐私政策、劳动法海报、校园地图…）
→ N 个产物**字节全同**、`is_complete_pdf()=True`、把 **0 产出站伪装成已打通**。

**实证**：某站 10 件产物 **MD5 全同**；某站 7 篇抓到同一个 campus-map。

**判据**：**多篇产物的 MD5 是否互异**。
→ **新增「PDF 优先」站前，必抽查 2 篇的 MD5 是否不同。**

**处置**：收紧 `pdf_pattern` 到站点内容路径 + 开 `pdf_same_host_only`。

### 同 MD5 分两类（处置相反）

| 类别 | 含义 | 处置 |
|---|---|---|
| 同文重复下载 | 真的下载了两遍 | 去重（删冗余） |
| **假壳页** | 不同 URL 拿到同一张通用 PDF | ★ **静默污染**，要连 URL 一起清 |

三件套：`_scan_dup_md5.py`（找）→ `_classify_dup_md5.py`（分类）→ `_dedupe_shell_pages.py`（清）。

## 五、批量抓完的**必跑清单**

```bash
# 1. 拦截页体检（最大口径错误）
python audit_artifacts.py --root ../reports

# 2. 重复 MD5 检查（通用 PDF 污染）
python audit_artifacts.py --root ../reports --check-md5

# 3. 隔离命中项（move，不删除）
python audit_artifacts.py --root ../reports --quarantine

# 4. 把「已标记但无产物」的 URL 放回 seen
python _purge_seen.py "<子串>" --apply
```

★ **隔离一律 `shutil.move` 到 `_quarantine_*/`，绝不 `rm`。**
（且注意：`os.remove` 常被 safe-delete 拦截 → 一律用 `shutil.move`。）

## 六、其他会「撑坏判据」的坑

| 坑 | 说明 |
|---|---|
| **AI 简报卡片撑长正文** | 判「正文过短」前**先剥** `<!-- AI BRIEFING CARD START -->` 区块 |
| **`subprocess.run(text=True)`** | 按系统 locale 解码 → 中文 Windows 是 GBK → 读 UTF-8 stdout 会**假失败** → 用 `encoding="utf-8"` |
| **`\r` 陷阱** | 站名带 `\r` → `--only` 全部匹配失败（3 秒/站空跑）→ `reconfigure(newline='\n')` + `tr -d '\r'` |
| **空标题** | 必须跳过 + `seen.discard()`，否则占位 |
| **同名不同内容** | 标题相同 → 后写的覆盖先写的 → 用日期前缀 + hash 区分 |

---

## 七、验收纪律

1. **验收看产物，不看日志**。日志说「成功」不等于文件是真内容。
2. **0 命中 / 全通过 先跑阳性对照**。全绿可能是判据坏了，不是系统健康。
3. **统计以磁盘产物为准**。`scan_all_reports()` 的数字才是真相，索引 JSON 可能滞后。
4. **「指标变好」要分清**：是修好了，还是把东西藏起来了（隔离 vs 修复）。
